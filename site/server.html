Run a server

One program, one folder, one port.

A Dead Drop server makes its own key, and phones recognise it by that key's fingerprint. It needs no domain name, no certificate authority and no other service. The smallest VPS a provider sells is enough, because it holds messages only until they are delivered.

  1. Get a Linux machine with a public address

    Ubuntu 24.04 or later is what the guide assumes. Note its IP address, or point a hostname at it. Whichever you choose goes into every invite, with port 7443.

  2. Lock it down

    The set-up script creates your user, turns off password logins, opens only SSH and port 7443, switches on automatic security updates and installs Docker.

    # bash setup-vps.sh <your-username> "<your SSH public key>"

  3. Get the code and say where the server is

    $ git clone https://github.com/edward-b-1/decentralizeddeaddrop.git
$ cd decentralizeddeaddrop/deploy
$ cp env.example .env
$ nano .env        # set DEADDROP_PUBLIC to <your address>:7443

  4. Start it

    The first build takes a few minutes. The log of the first start shows the fingerprint, a one-time operator token, and a link and QR code holding both.

    docker compose logs deaddropdfirst start
    $ docker compose up -d --build
$ docker compose logs --no-log-prefix deaddropd
    Made this server's key (/data/deaddrop.key.pem) and certificate (/data/deaddrop.cert.pem).
Keep the key file safe and backed up: phones recognise the server by it.

    Example output, captured from a throwaway server that no longer exists. Its address is one reserved for documentation, which no machine on the internet can have, and its fingerprint and token belong to nothing.

  5. Become the operator

    In the app: Servers, Add a server, Scan a QR code, and point the phone at the terminal. That phone now runs the server: it switches the ways in on and off, makes invites and approves devices.

  6. Let people in

    From the operator's phone: Servers, your server, Invite a device. Each invite lets one new phone on, once.

Prefer no Docker? The server is a single program with a systemd unit file. The full guide covers that, updating, and using a certificate of your own.

What to back up

Everything is in one folder. The key file matters most, and it never changes: back it up once, somewhere safe.

FileIf it is lost
deaddrop.key.pem
The server's key. Phones recognise the server by it.		Every phone refuses the server. Everyone has to add it again as a new one.
deaddrop.db
Who is registered, channels, member lists, messages not yet collected.		Everyone has to register and be invited again.

What the server logs

One line for each request, with no address and no identifier in it. The single exception is a wrong server password, which is logged with the address it came from so that a firewall tool can block the guesser.

2026-11-26T18:20:05Z password-failure from=203.0.113.7

Someone who knows the password is never recorded, and neither is anyone using another way in.

Ways in

The person running the server chooses which of these it accepts, and can combine them. Getting onto a server grants nothing inside it: every channel has its own owner and its own invites.
