Decentralized Dead Drop: send status mockup A

How your own messages show whether the server has taken them. Nothing here is built yet. Example names and addresses are made up.

What each state means

A message you send passes from the app's screen to the engine inside the phone, and from there to the server. The state says how far it has got. None of them says anything about the other members.

on the phone only
Waiting to send

The engine has sealed the message and is keeping it. The server has not taken it yet: no signal, or the server is having trouble. It goes by itself when the server answers.

on the server
Sent: no mark, only the time

The server has said yes and is holding the message for the other members. This is how every sent message looks today.

refused by the server
Not sent

The server has said no, and would say no again. The message stays on your phone only. Today this case looks exactly like "sent".

In a channel

The same conversation in each state.

In the list of channels

So that a message which did not go is noticed after you have left the conversation.

Choices this mockup makes

  1. A sent message carries no mark. Only the two unusual states are labelled, so a normal conversation looks as it does now.
  2. "Sent" means the server has it, and nothing more. There is still no report of who has collected or read a message.
  3. "Waiting to send" appears only after about a second, so that with a good signal the words do not flash under every message.
  4. A message that was not sent stays in the conversation until you delete it, with its text there to copy.
  5. No "try again" button. "Not sent" is shown only for a refusal that would be repeated. Anything that might work later stays "Waiting to send" and is retried without being asked.
  6. The channel list shows the state too (screen 5).
